## 🧱 Stack

A [Turborepo](https://turborepo.com) monorepo on pnpm workspaces. The site and the API behind it.

| Path                           | What it is                                                                                                       |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `apps/web`                     | SvelteKit 5 and Tailwind 4, prerendered and served by Caddy. Also packaged for Android and iOS through Capacitor |
| `apps/server`                  | Hono API with Drizzle ORM and better-auth. OpenAPI docs rendered by Scalar                                       |
| `packages/auth-shared`         | Auth types and access control shared by both apps                                                                |
| `packages/clashofclans-api`    | Hand-written, Redis-cached wrapper around the Clash of Clans API, used by the server                             |
| `packages/clashofclans-client` | Typed client for this repo's own API, generated by [kubb](https://kubb.dev) and used by web                      |
| `packages/*-config`            | Shared eslint, prettier and tsconfig presets                                                                     |

Data lives in Postgres 18, Redis 8 and [RustFS](https://rustfs.com) (S3-compatible storage for uploads), all run
through Docker Compose.

> [!IMPORTANT]
> Never hand-edit generated code. `apps/server/src/lib/db/schema/ba-auth.ts` comes from
> `pnpm --filter server ba:generate` and `packages/*-client/**` comes from kubb.

## 🚀 Getting started

You need [pnpm](https://pnpm.io/installation), [Node.js](https://nodejs.org) (version pinned in `.node-version`),
[Docker](https://docs.docker.com/get-started/get-docker) and [just](https://github.com/casey/just).

```sh
pnpm i

cp apps/server/.env.example apps/server/.env
cp apps/server/.env.server-db.example apps/server/.env.server-db
cp apps/web/.env.example apps/web/.env
```

The copied defaults cover the database, Redis and storage, but a few keys ship empty and the API refuses to boot
without them:

| Key                                                     | Where it comes from                                                                                                                               |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `JPA_AUTH_SECRET`                                       | `openssl rand -base64 32`                                                                                                                         |
| `JPA_DISCORD_ID`, `_SECRET`, `_BOT_TOKEN`               | A [Discord application](https://discord.com/developers/applications). Add `http://localhost:3000/api/auth/callback/discord` as an OAuth2 redirect |
| `JPA_COC_API_TOKEN`                                     | The [Clash of Clans developer portal](https://developer.clashofclans.com)                                                                         |
| `JPA_TURNSTILE_SECRET_KEY`, `PUBLIC_TURNSTILE_SITE_KEY` | Cloudflare's [Turnstile test keys](https://developers.cloudflare.com/turnstile/troubleshooting/testing/) work locally. Use a matching pair        |

Then bring up the services, apply the schema and start both apps:

```sh
just up
just db-migrate
pnpm run dev
```

| Service         | URL                   | Notes                                           |
| --------------- | --------------------- | ----------------------------------------------- |
| Web             | http://localhost:5173 | Vite dev server                                 |
| Server          | http://localhost:3000 | Scalar API docs at `/`, spec at `/openapi.json` |
| Postgres        | `localhost:7101`      | `postgres` / `postgres`, database `jpa`         |
| Redis           | `localhost:7102`      |                                                 |
| Drizzle Gateway | http://localhost:7103 | Database browser                                |
| Redis Insight   | http://localhost:7104 | Cache browser                                   |
| RustFS          | http://localhost:7105 | S3 API. Console on `:7106`                      |
| Spotlight       | http://localhost:8969 | Local Sentry errors and traces                  |

> [!TIP]
> Drizzle Gateway runs inside Docker, so it reaches Postgres at `jpa-db:5432`, not `localhost:7101`.

## 🛠️ Commands

Run `just` on its own to list every task.

| Command                    | What it does                                                                      |
| -------------------------- | --------------------------------------------------------------------------------- |
| `just up [profiles]`       | Start services. Profiles: `all` (default), `services`, `db`, `media`, `analytics` |
| `just down [profiles]`     | Stop them                                                                         |
| `just db-generate [name]`  | Write a migration from schema changes in `apps/server/src/lib/db/schema`          |
| `just db-migrate`          | Apply pending migrations                                                          |
| `just db-reset`            | Drop the local database volume. Run `just db-migrate` again after                 |
| `pnpm run dev`             | Web and server in watch mode                                                      |
| `pnpm run build`           | Build everything                                                                  |
| `pnpm run typecheck`       | Typecheck every workspace                                                         |
| `pnpm run lint` / `format` | ESLint and Prettier                                                               |

Scope any pnpm command to one app with `--filter`, e.g. `pnpm --filter web dev`.

## 📦 Deployment

Production runs on a single VPS behind Traefik and [Pangolin](https://github.com/fosrl/pangolin). On the server:

```sh
just prod          # git pull, build images, deploy and wait for healthchecks
just prod --down   # stop the stack
```

- Migrations run automatically every time the server container starts.
- `PUBLIC_*` variables are compiled into the web build, so changing one needs `just prod`, not a restart.
- Docker reads env files when a container is created. After editing a `.env`, recreate the container.
- `./restore.sh backup.zip` restores a Postgres backup. It **drops and recreates** the `jpa` database first.
